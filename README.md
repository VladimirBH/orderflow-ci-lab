# OrderFlow — CI Audit Lab · Advanced

Учебный сервис управления заказами с каталогом, скидками, резервированием остатков,
расчётами с поставщиками, правами доступа, платежами, уведомлениями, импортом и отчётами.

**Назначение:** комплексный аудит исходного кода через GitHub Actions, Ruff, Semgrep
и самостоятельные проверки бизнес-инвариантов. Проект содержит намеренно внесённые дефекты.
Не размещайте приложение в интернете и не используйте для реальных платежей.

## Быстрый запуск

```bash
python -m pip install pytest ruff semgrep
python -m pytest -q
ruff check src
semgrep scan --config rules/orderflow.yml --error --metrics=off src
```

Для веб-интерфейса (локально):

```bash
python -m pip install -e .
python -m orderflow.web
```

Проверка доступности: http://127.0.0.1:8765/health

### GitHub Actions

Файл `.github/workflows/ci.yml` содержит три независимых job: Unit tests,
Ruff quality gate и Semgrep security gate. Для начала практики ожидается,
что unit-тесты проходят, а часть анализаторов сообщает о нарушениях.

1. Создайте Fork учебного репозитория.
2. На вкладке Actions при необходимости разрешите выполнение workflow.
3. Создайте ветку `student/audit-<ваш-идентификатор>`.
4. Исследуйте найденные предупреждения; подтвердите важные из них кодом и тестами.
5. Исправьте причины, а не отключайте проверки.
6. Отправьте изменения в свой Fork и создайте Pull Request.

**Правила работы:** не редактируйте `rules/orderflow.yml` и workflow ради
«зелёной галочки»; не удаляйте тесты и проверяемые модули. Не все дефекты
выявляются стандартными правилами — исследуйте граничные случаи.

### Подсказка без ответов

Проверьте атомарность резервирования, возвраты сумм при округлении,
разграничение прав организаций, проверку адресов внешних сервисов,
повторные коды скидок, импорт табличных данных и сопоставление платежей.

## Отчёт по практической работе №7 (ветка `audit/mikhailov`)

**1. Аудит CI** — только `tests` исполняет код и проверяет реальное поведение; `quality`
(Ruff) и `security` (Semgrep) — статический анализ, который может пропустить
дефект или сработать на безопасный код.

| Требование | Инструмент | Критерий PASS | Область | Последствие нарушения |
|---|---|---|---|---|
| Нет неиспользуемых импортов/небезопасных замыканий (F401, B023) | Ruff | `ruff check src` → 0 | `src/` | недостижимый код, риск ошибки позднего связывания |
| Timing-safe сравнение ключей/подписи | Semgrep + unit-тесты | 0 находок, тесты успешно прошли | `accounts.py` | timing attack, обход аутентификации |
| Резервирование товара атомарно | `test_reservation_invariants.py` | `stock` не меняется при `False` | `fulfillment.py`, `inventory.py` | разные данные на складе и в заказах |
| JUnit-отчёт тестов — CI-артефакт | `actions/upload-artifact` | артефакт есть при любом исходе | `ci.yml`, job `tests` | долгая диагностика аварийных завершений |

**2. Диагностика находок** — до аудита (`main`) Ruff выводил 3 нарушения (2×`F401` + `B023`,
исправлены коммитами); Semgrep нашёл обход границы организации в
`access.py` (`admin`-роль пропускала проверку `tenant_id` — исправлено). Отдельно: правило
`orderflow-query-composition` написано именно под SQL-инъекции через f-строку, но не
сработало на реальную инъекцию в `storage.py` ни до, ни после исправления — **false negative**,
Успешное прохождения тестирования Semgrep здесь не означает «уязвимостей нет».

**3. Резервирование товара — найден и исправлен дефект.** `reserve_items` списывал остаток
построчно без отката: при неудаче на второй строке первая оставалась списанной. Добавлены
2 теста (`tests/test_reservation_invariants.py`):

| Сценарий | До исправления | После исправления |
|---|---|---|
| Атомарность (2 строки на 1 SKU > остатка) | `stock` портится, остаётся частично списан | `stock` не меняется, `False` |
| Граница (запрошен весь остаток) | уже работало | без изменений |
| SQL-инъекция в `find_orders_by_email` | payload `x' OR '1'='1'` возвращал все заказы | параметризованный запрос -> `[]` |

Исправлено по аналогии с `inventory.allocate_order` (проверка всех строк → затем списание).
Попутно исправлена и SQL-инъекция в `storage.py`. Все 26 тестов проходят, регрессий нет.

**4. CI:** добавлено сохранение JUnit-отчёта (`--junitxml`) как артефакта job `tests`. Также исправлен триггер `push`: ветки `audit/**`
не запускали Actions, добавлены в `branches`.
